BMSPartTuner 次世代数理最適化戦略 (限界突破の数理モデル)¶

現在の実装（RMSベースの三角不等式枝刈り、正規化ドット積のSIMD化）からさらに計算量を削ぎ落とし、ハードウェアリソースを極限まで使い切るための高度な最適化戦略です。アプリ全体の実行時間に対する「削減効果（インパクト）が高いと予想される順」にランキング化して優先順位を定めています。

【S級：圧倒的インパクト】計算空間そのものを消滅させる¶

1位. グラフ理論の拡張：「負の推移律」を活用した比較空間の崩壊¶

  • 対象クラス: ParallelAudioComparisonEngine
  • 適用ヒント: 状態空間の削減、負の推移律 (Anti-Set)

【What】 「AとBは違う」という膨大な計算結果をキャッシュし、「BとCが同じなら、AとCも計算するまでもなく違う」と連鎖的に計算をスキップさせます。

【Why】 BMSのデータセットでは「似ているペア」よりも「似ていないペア」の方が圧倒的に多い特性があります。現在の「正の推移律（Union-Find）」は似ているものを見つけた時にしか枝刈りが働きません。負の推移律を導入して比較空間を崩壊させることは、理論上最大の計算量削減（O記法での定数倍の大幅な削減）をもたらします。

【A級：強力な足切り】重いSIMD計算をさせない¶

2位. 次元圧縮とカスケード分類：DCTによる低次元射影¶

  • 対象クラス: FastWaveCompare の事前処理
  • 適用ヒント: 状態空間の削減、演算強度の低減

【What】 数千〜数万次元ある波形データを「8次元〜16次元」の特徴量ベクトルに圧縮（離散コサイン変換: DCT）し、その超低次元空間のユークリッド距離で事前の足切りを行います。

【How】 波形のロード時にDCTをかけ、低周波数帯の係数だけを抽出して保存します。比較時、この8次元ベクトルが一定値以上離れていれば「絶対に一致しない」と数学的に保証されるため、フル波形のSIMD比較をスキップします。

【Why】 負の推移律をすり抜けたペアに対して、いきなり数万サンプルの波形を読み込んでSIMDを回すのは高コストです。波形のエネルギー構造は低周波数帯に集中するため、DCTによって超低次元に圧縮して足切りを行うことで、「本当に似ている可能性が高い数％のペア」だけに重いSIMD計算を許容できます。

3位. 状態空間の削減と緩和：SimHash と POPCNT による超高速スクリーニング¶

  • 対象クラス: ParallelAudioComparisonEngine
  • 適用ヒント: 緩和問題の利用、演算強度の低減

【What】 波形を256bit程度のシグネチャ（SimHash）に圧縮し、XORと POPCNT (ハミング距離) で似ていないペアを瞬時に弾きます。

【Why】 思想はDCTと同じ「足切り」ですが、こちらは「CPUのハードウェア命令（POPCNT）」に極限まで最適化しています。1ペアが数クロックで終わるため、DCTの変換計算すら重いと感じる場合の強力な代替手段となります。

【B級：ハードウェア限界突破】避けられない計算を爆速にする¶

4位. ハードウェアマッピング：SoA (Structure of Arrays) による多重ペア同時比較 [採用見送り]¶

  • 対象クラス: FastWaveCompare / WaveValidation
  • 適用ヒント: メモリレイアウトの最適化 (AoS -> SoA)、SIMD/ベクトル化

【What】 波形データを比較対象グループ単位でインターリーブ（交差）させ、「Aと[B, C, D, E]を同時に比較」するメモリレイアウトに変更します。

【Why】 足切りを通過してフル波形比較が必要になったペアに対して効きます。現代のCPUは計算速度よりメモリ帯域（メモリウォール）で詰まるため、SoAレイアウトにしてL1/L2キャッシュのヒット率を最大化させることは、ハードウェアの理論限界値（FLOPS）に近づける決定打になります。

【Result: 実装見送り (Rejected)】 このアプローチは実験的に実装が試みられましたが、計算順序や浮動小数点の丸め誤差（精度問題）、あるいはメモリアクセス境界の変化により、571件の統合テスト（V1.0.0.0との決定論的出力の一致検証）で失敗（リグレッション）が発生したため、あえて実装しない判断を下しました。 キャッシュ効率よりも、音ゲーとしての品質を担保するテストの完全合格を優先しています。

【C級・D級：局所的な最適化】 [採用見送り]¶

5位. 精度妥協と動的計画法：階層的 FFT (Coarse-to-Fine Alignment) [採用見送り]¶

  • 対象クラス: FftAlignmentEngine
  • 適用ヒント: 精度の妥協（混合精度演算）、緩和問題

【What】 波形を 1/16 等に間引いて低解像度のFFT相互相関で大まかなズレを特定し、その狭い範囲に対してのみ時間領域での厳密な相互相関を行います。

【Why】 \(O(N \log N)\) のFFTは重い処理ですが、全てのペアで実行されるわけではないため、全体の処理時間に占める割合としては上位のアプローチに劣りますが、実行経路では劇的な高速化をもたらします。

【Result: 実装見送り (Rejected)】 S級・A級（Anti-Set、Diagonal Sweep、16D Spectral Projection、SimHash256 カスケード）の実装により、アライメント計算の前段でほとんどのペアが極めて高速に枝刈りされるようになりました。アライメント（FFT）自体が実行される頻度が極端に少なくなったため、開発コスト（ROI）および精度低下リスクを考慮し、あえて実装しない（現状維持）決定を下しました。

6位. 演算強度の低減：LSHキャッシュを活用した O(1) 整数無音判定 [採用見送り]¶

  • 対象クラス: SilenceTrimmer
  • 適用ヒント: 乗除算から加減算への変換、高コスト関数の回避

【What】 O(1) スライディングウィンドウの浮動小数点の2乗和を、LSHマスクを用いた64bit整数の POPCNT の合計に置き換えます。

【Why】 すでに現在の浮動小数点 O(1) ウィンドウで最速に達しているため、整数ビット演算にする効果は局所的であり、全体から見ればマイクロオプティマイゼーションに留まります。

【Result: 実装見送り (Rejected)】 SilenceTrimmer に対し、MemoryMarshal と Avx2.MultiplyAddAdjacent を用いたネイティブ SIMD 演算を実装したことで、無音トリミングの実行速度はボトルネックから完全に除外されるレベルに達しました。これ以上の複雑な整数ビットへの近似変換は、コードの可読性を下げバグの原因になり得るため、あえて実装しない（現状維持）決定を下しました。
